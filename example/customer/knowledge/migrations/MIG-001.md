Adds `customer.deleted_at`, nullable.

## Why

BR-003 requires a deleted customer to be distinguishable from one that never
existed. Version 1 recorded *that* a customer was deleted and not *when*, which
was enough to satisfy the rule and not enough to answer support questions about
retention, and the two came apart the first time anyone asked.

## The backfill, and why it is a compromise

Rows deleted before this migration have no recorded deletion time, and none can
be recovered, so the value is inferred from the last modification of the row.
That is an approximation and this file is the only place that says so. A reader
who finds a `deleted_at` equal to the epoch is looking at a customer deleted
before 2026-08-07, not one deleted in 1970.

## Reversible, unusually

Dropping the column loses only data this migration invented, so reversing it
returns the system to a state it was genuinely in before. Most migrations are
not like this, and `reversible: true` should be read as a claim about this one
rather than a habit.
